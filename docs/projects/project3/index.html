Introduction

Every software company eventually faces the same question: does our product actually work? For Blueprinty — a firm that builds patent-application drafting software for engineering companies — this question has real stakes. Their marketing team wants to claim that firms using Blueprinty’s platform win more patents. The raw numbers look promising: customers average 4.1 patents over five years versus 3.5 for non-customers. But a raw comparison is not enough.

The fundamental problem is selection bias. Blueprinty’s customers are not a random sample of engineering firms. A company that bothers to invest in specialized patent software is likely already more sophisticated, better funded, or more patent-active than average. Any difference in patent counts could simply reflect who buys the software rather than what the software does.

To cut through this, we need a regression model — something that can hold age and location fixed while estimating the customer effect cleanly. The outcome (patents over five years) is a non-negative integer count, which calls for a Poisson regression estimated by Maximum Likelihood. This post walks through the MLE recipe from first principles: derive the likelihood, code it up, maximize it numerically, verify it against a standard GLM, and finally translate the coefficient into a plain-English business answer.

Age and Regional Composition

A Simple Poisson Model via MLE

Why Poisson?

The Normal distribution is the workhorse of regression, but it allows negative values — meaningless for patent counts. The Poisson distribution is purpose-built for non-negative integer outcomes. A count variable \(Y\) follows \(\text{Poisson}(\lambda)\) if

\[ f(Y \mid \lambda) = \frac{e^{-\lambda}\,\lambda^{Y}}{Y!}, \qquad Y = 0,1,2,\ldots \]

The single parameter \(\lambda > 0\) is simultaneously the mean and the variance. It has a natural interpretation: \(\lambda\) is the expected number of events in the observation window.

Likelihood and Log-Likelihood

Assuming the \(n = 1{,}500\) observations are independent, the joint likelihood is

\[ L(\lambda \mid \mathbf{Y}) = \prod_{i=1}^{n} \frac{e^{-\lambda}\,\lambda^{Y_i}}{Y_i!} \]

Taking the log (which is monotone, so it preserves the maximizer):

\[ \ell(\lambda) = \log L = \sum_{i=1}^{n}\Bigl(Y_i \log\lambda - \lambda - \log(Y_i!)\Bigr) = \left(\sum_i Y_i\right)\log\lambda \;-\; n\lambda \;-\; \sum_i \log(Y_i!) \]

The last term does not depend on \(\lambda\), so it drops out of the optimization. The MLE is the \(\lambda\) that maximizes \(\ell(\lambda)\).

Analytic solution: Setting \(\frac{d\ell}{d\lambda} = 0\):

\[ \frac{d\ell}{d\lambda} = \frac{\sum_i Y_i}{\lambda} - n = 0 \quad\Longrightarrow\quad \hat\lambda_{\text{MLE}} = \frac{\sum_i Y_i}{n} = \bar{Y} \]

The MLE is simply the sample mean — intuitive, because \(\lambda = E[Y]\) for the Poisson.

Coding and Plotting the Log-Likelihood

Code 
def poisson_loglik(lam, Y):
    """Log-likelihood of Poisson(lam) for data Y (scalar lambda)."""
    if lam <= 0:
        return -np.inf
    return np.sum(Y * np.log(lam) - lam) - np.sum(special.gammaln(Y + 1))

lam_grid = np.linspace(2.5, 5.0, 300)
ll_vals  = [poisson_loglik(lam, Y) for lam in lam_grid]

y_mean = Y.mean()

fig, ax = plt.subplots(figsize=(9, 4))
ax.plot(lam_grid, ll_vals, color=BLUE, lw=2.5)
ax.axvline(y_mean, color="crimson", lw=2, ls="--", label=f"MLE = $\\bar{{Y}}$ = {y_mean:.4f}")
ax.set_xlabel("λ  (expected patent count)", fontsize=12)
ax.set_ylabel("Log-likelihood  ℓ(λ)", fontsize=12)
ax.set_title("Poisson Log-Likelihood", fontsize=13, fontweight="bold")
ax.legend(frameon=False, fontsize=11)
plt.tight_layout()
plt.show()

The curve is concave with a single peak — the MLE sits exactly where we’d read off the maximum visually. The shape illustrates why MLE works: as \(\lambda\) moves away from \(\bar{Y}\) in either direction, the data become exponentially less probable.

Poisson Regression

Extending to Firm-Level Covariates

The simple model above treats all 1,500 firms as if they have the same expected patent rate \(\lambda\). That is clearly wrong — older, Northeastern firms are more patent-active. In Poisson regression, each firm gets its own \(\lambda_i\):

\[ Y_i \sim \text{Poisson}(\lambda_i), \qquad \lambda_i = \exp(X_i'\beta) \]

The exponential link \(\exp(\cdot)\) is essential: \(X_i'\beta\) can be any real number, but \(\lambda_i\) must be strictly positive. Exponentiating maps the linear predictor onto \((0, \infty)\) automatically.

The log-likelihood becomes

\[ \ell(\beta) = \sum_{i=1}^n \Bigl[ Y_i\,(X_i'\beta) - \exp(X_i'\beta) - \log(Y_i!) \Bigr] \]

Two design choices deserve mention:

  • Age-squared is included because the age–patenting relationship is unlikely to be linear. Young firms are still building capabilities; very old firms may have mature product lines with little to patent. A quadratic term captures this inverted-U.

  • One region is dropped (Midwest here) to avoid perfect collinearity: the sum of all region dummies equals 1, which equals the intercept column. Dropping one makes the system identifiable; all remaining coefficients are interpreted relative to Midwest firms.

Coding the Regression Log-Likelihood

Code 
def poisson_reg_loglik(beta, Y, X):
    """Log-likelihood for Poisson regression."""
    eta      = X @ beta                       # linear predictor
    lam      = np.exp(eta)                    # expected counts
    log_fac  = np.sum(special.gammaln(Y + 1)) # Σ log(Y!)
    return np.sum(Y * eta - lam) - log_fac

Maximizing with scipy.optimize

Code 
X_arr = X.values
beta0 = np.zeros(X_arr.shape[1])

opt = optimize.minimize(
    fun     = lambda b: -poisson_reg_loglik(b, Y, X_arr),
    x0      = beta0,
    method  = "BFGS",
    options = {"maxiter": 2000},
)

beta_hat = opt.x

# Standard errors from the Hessian via finite-difference
from scipy.optimize import approx_fprime
h = 1e-5
n_params = len(beta_hat)
H = np.zeros((n_params, n_params))
for i in range(n_params):
    def grad_i(b):
        return approx_fprime(b, lambda bb: -poisson_reg_loglik(bb, Y, X_arr), h)[i]
    H[i] = approx_fprime(beta_hat, grad_i, h)

se_hat = np.sqrt(np.diag(np.linalg.inv(H)))

Verifying Against statsmodels

Code 
glm_model  = sm.GLM(Y, X, family=sm.families.Poisson())
glm_result = glm_model.fit()

The manual MLE coefficients match the GLM output almost exactly. Tiny differences in standard errors are normal — scipy approximates the Hessian numerically via finite differences, while statsmodels uses the exact Fisher information matrix from the IRLS algorithm. Both are valid; the GLM standard errors are generally more precise.

The Effect of Blueprinty’s Software

A Poisson coefficient is not directly an “extra patent” number — the model is multiplicative, so the effect depends on a firm’s baseline. To get a plain-English number, we use the counterfactual prediction approach.

Code 
# Two counterfactual matrices
X0 = X.copy(); X0["iscustomer"] = 0   # all firms treated as non-customers
X1 = X.copy(); X1["iscustomer"] = 1   # all firms treated as customers

# Predicted patent counts under each scenario
y_hat_0 = glm_result.predict(X0)
y_hat_1 = glm_result.predict(X1)

ate = (y_hat_1 - y_hat_0).mean()
print(f"Average predicted patents (no Blueprinty)  : {y_hat_0.mean():.4f}")
print(f"Average predicted patents (with Blueprinty): {y_hat_1.mean():.4f}")
print(f"Average Treatment Effect (ATE)             : {ate:.4f}")
Average predicted patents (no Blueprinty)  : 3.4362
Average predicted patents (with Blueprinty): 4.2290
Average Treatment Effect (ATE)             : 0.7928

Bottom Line

Holding firm age and region fixed at their observed values, a firm that uses Blueprinty’s software is predicted to receive about 0.79 more patents over five years on average. Given a baseline of roughly 3.5 patents for non-customers, that represents a ~23% increase — a commercially meaningful effect.

What This Analysis Does and Does Not Establish

This is an observational study, not a randomized experiment. The model controls for age and region, but there may be unmeasured differences between customers and non-customers — R&D investment, engineering talent, prior patent experience — that could partially explain the gap. A proper causal claim would require either a randomized trial or a natural experiment (e.g., staggered software rollout across offices).

That said, the result is statistically robust (p < 0.001) and survives conditioning on the most obvious confounders. The evidence is consistent with Blueprinty’s marketing claim, and the magnitude is large enough to be practically significant. A careful statement to the marketing team: “Our data show that customers win about 0.79 more patents per five-year window than otherwise-similar non-customers. This is strong suggestive evidence of software value, but we cannot rule out unobserved firm quality driving part of the effect.”

## A Simple Poisson Model via MLE

### Why Poisson?

The Normal distribution is the workhorse of regression, but it allows negative values — meaningless for patent counts. The Poisson distribution is purpose-built for non-negative integer outcomes. A count variable $Y$ follows $\text{Poisson}(\lambda)$ if

$$
f(Y \mid \lambda) = \frac{e^{-\lambda}\,\lambda^{Y}}{Y!}, \qquad Y = 0,1,2,\ldots
$$

The single parameter $\lambda > 0$ is simultaneously the mean *and* the variance. It has a natural interpretation: $\lambda$ is the expected number of events in the observation window.

### Likelihood and Log-Likelihood

Assuming the $n = 1{,}500$ observations are independent, the **joint likelihood** is

$$
L(\lambda \mid \mathbf{Y}) = \prod_{i=1}^{n} \frac{e^{-\lambda}\,\lambda^{Y_i}}{Y_i!}
$$

Taking the log (which is monotone, so it preserves the maximizer):

$$
\ell(\lambda) = \log L = \sum_{i=1}^{n}\Bigl(Y_i \log\lambda - \lambda - \log(Y_i!)\Bigr)
= \left(\sum_i Y_i\right)\log\lambda \;-\; n\lambda \;-\; \sum_i \log(Y_i!)
$$

The last term does not depend on $\lambda$, so it drops out of the optimization. The MLE is the $\lambda$ that maximizes $\ell(\lambda)$.

**Analytic solution:** Setting $\frac{d\ell}{d\lambda} = 0$:

$$
\frac{d\ell}{d\lambda} = \frac{\sum_i Y_i}{\lambda} - n = 0 \quad\Longrightarrow\quad \hat\lambda_{\text{MLE}} = \frac{\sum_i Y_i}{n} = \bar{Y}
$$

The MLE is simply the sample mean — intuitive, because $\lambda = E[Y]$ for the Poisson.

```{python}
def poisson_reg_loglik(beta, Y, X):
    """Log-likelihood for Poisson regression."""
    eta      = X @ beta                       # linear predictor
    lam      = np.exp(eta)                    # expected counts
    log_fac  = np.sum(special.gammaln(Y + 1)) # Σ log(Y!)
    return np.sum(Y * eta - lam) - log_fac
```

### Maximizing with `scipy.optimize`

```{python}
#| echo: true

X_arr = X.values
beta0 = np.zeros(X_arr.shape[1])

opt = optimize.minimize(
    fun     = lambda b: -poisson_reg_loglik(b, Y, X_arr),
    x0      = beta0,
    method  = "BFGS",
    options = {"maxiter": 2000},
)

beta_hat = opt.x

# Standard errors from the Hessian via finite-difference
from scipy.optimize import approx_fprime
h = 1e-5
n_params = len(beta_hat)
H = np.zeros((n_params, n_params))
for i in range(n_params):
    def grad_i(b):
        return approx_fprime(b, lambda bb: -poisson_reg_loglik(bb, Y, X_arr), h)[i]
    H[i] = approx_fprime(beta_hat, grad_i, h)

se_hat = np.sqrt(np.diag(np.linalg.inv(H)))
```

## The Effect of Blueprinty's Software

A Poisson coefficient is not directly an "extra patent" number — the model is multiplicative, so the effect depends on a firm's baseline. To get a plain-English number, we use the **counterfactual prediction** approach.

```{python}
#| echo: true

# Two counterfactual matrices
X0 = X.copy(); X0["iscustomer"] = 0   # all firms treated as non-customers
X1 = X.copy(); X1["iscustomer"] = 1   # all firms treated as customers

# Predicted patent counts under each scenario
y_hat_0 = glm_result.predict(X0)
y_hat_1 = glm_result.predict(X1)

ate = (y_hat_1 - y_hat_0).mean()
print(f"Average predicted patents (no Blueprinty)  : {y_hat_0.mean():.4f}")
print(f"Average predicted patents (with Blueprinty): {y_hat_1.mean():.4f}")
print(f"Average Treatment Effect (ATE)             : {ate:.4f}")
```

```{python}
#| echo: false

#| fig-cap: "Distribution of the individual-level treatment effect (ŷ₁ − ŷ₀) across all 1,500 firms."

fig, ax = plt.subplots(figsize=(9, 4))
ax.hist(diffs, bins=40, color=BLUE, edgecolor="white", linewidth=0.5, alpha=0.85, density=True)
ax.axvline(ate, color="crimson", lw=2.5, ls="--", label=f"Mean ATE = {ate:.3f}")
ax.set_xlabel("Extra Patents from Using Blueprinty  (ŷ₁ − ŷ₀)", fontsize=12)

plt.tight_layout()
plt.show()
```

### Bottom Line

Holding firm age and region fixed at their observed values, **a firm that uses Blueprinty's software is predicted to receive about 0.79 more patents over five years** on average. Given a baseline of roughly 3.5 patents for non-customers, that represents a **~23% increase** — a commercially meaningful effect.

### What This Analysis Does and Does Not Establish

This is an observational study, not a randomized experiment. The model controls for age and region, but there may be unmeasured differences between customers and non-customers — R&D investment, engineering talent, prior patent experience — that could partially explain the gap. A proper causal claim would require either a randomized trial or a natural experiment (e.g., staggered software rollout across offices).

That said, the result is statistically robust (p < 0.001) and survives conditioning on the most obvious confounders. The evidence is *consistent* with Blueprinty's marketing claim, and the magnitude is large enough to be practically significant. A careful statement to the marketing team: *"Our data show that customers win about 0.79 more patents per five-year window than otherwise-similar non-customers. This is strong suggestive evidence of software value, but we cannot rule out unobserved firm quality driving part of the effect."*
